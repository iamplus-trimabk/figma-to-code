## 🏗️ **System Architecture**

### **Component Overview**
```
Stage 3 Component Generator
├── Templates (Jinja2)
│   ├── components/     # Component templates
│   ├── partials/       # Reusable template fragments
│   └── scripts/        # Generation scripts
├── Stage 2 Outputs     # Design tokens & interfaces
├── Generated Components (src/components/)
│   ├── navigation/     # Button, Tabs, etc.
│   ├── forms/         # Input, Select, etc.
│   ├── display/       # Card, Badge, etc.
│   └── feedback/      # Alert, Modal, etc.
└── Configuration      # Component definitions
```

### **Technology Stack**
- **Template Engine**: Jinja2 (Python)
- **Frontend**: React 18 + TypeScript
- **Styling**: Tailwind CSS v4
- **Build System**: Next.js 15
- **Quality**: ESLint + Prettier + TypeScript

## 🔧 **Component Generation Workflow**

### **Step 1: Component Definition**
Components are defined in `stage_2_outputs/web_config.json`:

```json
{
  "componentInterfaces": {
    "MyComponent": {
      "category": "forms",
      "props": [
        {
          "name": "variant",
          "type": "primary | secondary | outline",
          "default": "primary"
        },
        {
          "name": "size",
          "type": "sm | md | lg",
          "default": "md"
        }
      ]
    }
  }
}
```

### **Step 2: Template Selection**
The system automatically selects the appropriate template based on component category:

- **navigation** → Interactive components with click handlers
- **forms** → Input components with validation states
- **display** → Visual components with layout props
- **feedback** → Status components with visibility controls

### **Step 3: Generation Process**
```bash
# Command structure
python3 templates/scripts/component_generator.py \
  --stage2 <path_to_stage2_outputs> \
  --component <component_name> \
  --platform <web|mobile> \
  --output <optional_output_path>
```

### **Step 4: Output Structure**
Generated components follow this structure:
```typescript
// src/components/[category]/[component].tsx
/**
 * Component Name - Generated by Stage 3 Component Generator
 */
"use client"

import * as React from "react"
import { cva } from "class-variance-authority"

// Design tokens from Stage 2

// Component variants
const componentVariants = cva(/* ... */)

// Component interface
export interface ComponentProps extends /* ... */ {}

// Component implementation

export { Component, componentVariants }
```

```python
def _token_to_css_class(self, token_value: str) -> str:
    """Convert design token to Tailwind CSS class"""
    if token_value.startswith('#'):
        return f"[{token_value}]"  # Arbitrary value
    return token_value.replace('_', '-')

# Register custom filter
env.filters['css_class'] = self._token_to_css_class
```

## 🎯 **Design Token Integration**

### **Token Structure**
Design tokens are loaded from `stage_2_outputs/web_config.json`:

```json
{
  "colorPalette": {
    "primary": {
      "50": "#f7f6fd",
      "500": "#6257db",
      "600": "#584ec5"
    },
    "success": {
      "50": "#f4fbf5",
      "500": "#28b446"
    }
  },
  "typography": {
    "fontFamily": {
      "Poppins": ["Poppins", "sans-serif"]
    },
    "fontWeight": {
      "medium": "500",
      "semibold": "600"
    }
  },
  "spacing": {
    "2": "8px",
    "3": "13px",
    "4": "16px"
  }
}
```

### **Token Usage in Templates**
```jinja2
{# Access color tokens #}
bg-primary-500 hover:bg-primary-600

{# Access spacing tokens #}
px-{{ design_tokens.spacing['3'] | replace('px', '') }}
py-{{ design_tokens.spacing['2'] | replace('px', '') }}

{# Access typography tokens #}
font-{{ design_tokens.typography.fontWeight.medium }}
```

### **Custom Token Processing**
```python
def _process_design_tokens(self, tokens: dict) -> dict:
    """Process design tokens for template consumption"""
    processed = {}

    # Color tokens
    if 'colorPalette' in tokens:
        colors = {}
        for color_name, color_values in tokens['colorPalette'].items():
            colors[color_name] = color_values
        processed['colors'] = colors

    # Spacing tokens
    if 'spacing' in tokens:
        spacing = {}
        for key, value in tokens['spacing'].items():
            # Convert "8px" to "2" for Tailwind
            spacing[key] = value.replace('px', '')
        processed['spacing'] = spacing

    return processed
```

## 🔍 **Troubleshooting Guide**

### **Common Issues**

#### **1. Template Not Found**
```
Error: Template not found: components/special-component.j2
```
**Solution**: Create the template or use the base component template:
```bash
# Use base template for special cases
python3 templates/scripts/component_generator.py \
  --stage2 stage_2_outputs/ \
  --component specialComponent \
  --template components/component.j2
```

#### **2. Design Token Missing**
```
Error: Design token not found: colors.primary.500
```
**Solution**: Check the design token structure:
```python
# Debug token structure
python3 -c "
import json
with open('stage_2_outputs/web_config.json') as f:
    data = json.load(f)
    print('Available colors:', list(data.get('colorPalette', {}).keys()))
"
```

#### **3. TypeScript Compilation Errors**
```
Error: TS2322: Type 'string' is not assignable to type 'boolean'
```
**Solution**: Check component interface definition:
```typescript
// Ensure proper TypeScript types
export interface ComponentProps {
  disabled?: boolean        // ✅ Correct
  // disabled?: string      // ❌ Wrong
}
```

#### **4. Styling Not Applied**
```
Tailwind classes not working
```
**Solution**: Verify PostCSS configuration and build:
```bash
# Check PostCSS config
cat postcss.config.js

# Rebuild CSS
rm -rf .next
npm run dev
```

### **Debug Mode**
Enable debug output for troubleshooting:
```python
# In component_generator.py
import logging
logging.basicConfig(level=logging.DEBUG)

# Or use verbose flag
python3 templates/scripts/component_generator.py \
  --stage2 stage_2_outputs/ \
  --component button \
  --verbose
```

### **Component Validation**
```bash
# Validate generated component
npx tsc --noEmit src/components/navigation/button.tsx

# Check component in browser
npm run dev
# Visit: http://localhost:3000/components
```

## 💡 **Best Practices**

### **1. Component Design**
- ✅ **Single Responsibility**: Each component does one thing well
- ✅ **Consistent Props**: Use standard prop names across components
- ✅ **Accessibility**: Include ARIA attributes and keyboard navigation
- ✅ **Type Safety**: Provide comprehensive TypeScript interfaces

### **2. Template Development**
- ✅ **DRY Principle**: Use partials for reusable template sections
- ✅ **Clear Naming**: Use descriptive template and variable names
- ✅ **Commentary**: Add Jinja2 comments for complex logic
- ✅ **Error Handling**: Graceful fallbacks for missing tokens

### **3. Design Token Usage**
- ✅ **Token Consistency**: Use design tokens consistently across components
- ✅ **Semantic Naming**: Use semantic token names (primary, success, etc.)
- ✅ **Fallback Values**: Provide fallbacks for missing tokens
- ✅ **Token Validation**: Validate token existence before usage

### **4. Performance Optimization**
- ✅ **Template Caching**: Leverage Jinja2 template caching
- ✅ **Incremental Generation**: Only regenerate changed components
- ✅ **Memory Efficiency**: Clean up unused variables and imports
- ✅ **Build Optimization**: Use production builds for deployment

Create new component categories by adding templates:

```bash
def _get_component_category(self, component_name: str) -> str:
    categories = {
        'barChart': 'charts',
        'pieChart': 'charts',
        'lineChart': 'charts',
        # ... existing categories

    return categories.get(component_name, 'display')
```
